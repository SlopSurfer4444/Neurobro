The CLI/setup sections below document the original ingestion commands; they are not a full deployment guide for the standing assistant. See the [repository README](../../README.md).

# Guarded MTProto Ingestor

Пакет содержит исходный CLI для чтения Telegram и standing-сервис Нейробро:
маршрутизацию обращений, память, поиск, длительные задачи, инструменты и
доставку результатов. Шлюз работает через пользовательский аккаунт GramJS/MTProto;
мост Node/Python связывает его с внешним Codex App Server в WSL.
Рабочая группа и необязательный источник только для чтения привязываются отдельно.

Текущая [архитектура](../../docs/architecture.md) и
[проверки](../../docs/testing.md) описаны в документации репозитория.
Разделы ниже относятся к отдельным модулям и исходному CLI; они не являются
полной инструкцией установки постоянного ассистента.

## Мост Windows ↔ WSL: текущий офлайн-срез

`wsl-broker-contract.ts`, `wsl-broker-host.ts` и `wsl-broker-guest.ts` реализуют
небольшой канал поверх уже открытых stdio pipes. Модуль не запускает WSL,
не открывает TCP-порт и не создаёт Telegram-клиент. Проверка:
`npm run test:wsl-broker`. Это проверка кода и транспорта на искусственных
данных; она не означает установку моста в гостевой системе или live-доступ.

Дополнительно проверяется отдельный Node-процесс: запросы и ответы проходят
через настоящие stdin/stdout pipes, с чтением snapshot, primary text и возвратом
proposal. В этом тесте ключ выдуман и публичен; доставка рабочего ключа,
запуск Linux-процесса и изоляция модельных инструментов им не проверяются.

`wsl-broker-snapshot.ts` — отдельный загрузчик для доверенной Windows-стороны.
Он читает только явно выбранные текстовые файлы из точного принятого Git-коммита
и дерева. Рабочие изменения и новый HEAD не меняют выбранный снимок.
Принятый commit/tree и список файлов задаёт доверенный владелец запуска:
загрузчик проверяет их целостность, но сам не принимает Git-коммиты.
Гостевые методы получают готовый снимок; Git-команды и путь репозитория
в гостевой API не передаются. Проверки используют настоящий локальный Git
и временный репозиторий с искусственным содержимым, без сети.
Поддерживается обычный локальный `.git` с локальными объектами; worktree-ссылки,
include-конфигурации и внешние object stores отклоняются. Во время загрузки
метаданные `.git` остаются под контролем доверенного владельца: это не защита
от параллельного вредоносного процесса, меняющего файловую систему хоста.

Host принимает только `snapshot.list/read/search`, пять primary-context
методов `telegram.anchor.read`, `telegram.range.read`,
`telegram.reply_chain.read`, `telegram.search`,
`telegram.media_derivative.read` и `proposal.submit`. Primary text проходит
без summary и остаётся недоверенными данными. Media derivatives обозначаются
отдельно. Нет произвольных команд, host paths, Git/process/shell API или
сетевого proxy.

Перед запуском доверенный host composition передаёт неизменяемый curated
снимок accepted commit/tree и отдельную функцию проверки его принятия.
Мост копирует данные в память, проверяет SHA-256, file modes и относительные
пути; symlink modes, traversal, `.git`, `.env` и session/credential paths
отклоняются. На запросах файловая система не читается. Эта граница не заменяет
проверку происхождения снимка: функция `acceptsSnapshot` должна опираться на
принятую authority, а не на утверждение гостя.

Каждое соединение получает fresh random session id и secret HMAC key от
доверенного launcher. Ключ остаётся в transport closure; модель получает
только `request()`, а не session options. Canonical UTF-8 JSONL, direction,
session/key ids, request id, последовательность, deadline и body связаны
HMAC-SHA-256. Дубли JSON-ключей, лишние поля, reflection, replay и sequence
gaps отклоняются. Потерянный/неизвестный результат закрывает сеанс без retry;
для нового соединения нужен новый session id/key, а не сброс sequence.

Пределы по умолчанию: frame 32 KiB, body 24000 bytes, text 16 KiB,
64 items/page, 32 calls/session, 256 KiB/session и 5 seconds/call.
Host может только уменьшать пределы. Snapshot ограничен 256 файлами/1 MiB.
Вызовы последовательны. При timeout AbortSignal передаётся владельцу;
он обязан завершать свою работу, а pipe owner — закрывать принадлежащие ему
потоки через `closePipes`. Код не заявляет принудительное завершение чужого
процесса или callback, игнорирующего cancellation.

`SoleGatewayContextOwner` — capability существующего единственного владельца
Telegram-сессии. Здесь проверен fixture owner. Существующий `./api` умеет
только list/recent; он не выдаётся за реализацию всех пяти новых методов.
Для live composition потребуется отдельно подключить соответствующие
primary readers и сохранить owner lease/consent/retention gates.

`proposal.submit` передаёт только reply proposal в injected guarded outbox
owner после exact-chat, kill switch, byte/call budget и session dedupe.
`queued` означает постановку предложения, не отправку. Durable dedupe между
сеансами, повторная проверка kill switch непосредственно перед отправкой,
read-after-write и reconcile остаются обязанностью существующего outbox.
Никакого метода send или снятия unknown этот мост не предоставляет.
Успешный `no_op` не требует outbound-вызова.

Raw-free receipts имеют фиксированные поля: version, calls, requestBytes,
responseBytes, outcome. Они не содержат текст, путь, chat/anchor/request ids,
query или content hashes. Мост не создаёт гостевое хранилище raw messages.
Login, model, autostart и Telegram live-send этим офлайн-срезом не включаются.

Готовый консервативный модуль подключения собственного Telegram-аккаунта через MTProto и
GramJS — по той же технической схеме, что community userbot OpenClaw, но без Telethon и без
исходящих действий.

Нулевой риск блокировки гарантировать невозможно: Telegram сам назначает динамические лимиты,
наблюдает за неофициальными клиентами и принимает серверные антиспам-решения. Здесь нет маскировки
клиента или обхода антиабьюза. Защита строится на минимуме запросов, явных границах и немедленной
остановке по серверным сигналам.

## Что модуль делает

- авторизует уже существующий аккаунт через `api_id`/`api_hash` и код входа;
- шифрует `StringSession` AES-256-GCM с ключом из scrypt-пароля;
- показывает до 100 текущих диалогов для выбора точного numeric `peerId`;
- проверяет авторизацию без чтения списка диалогов (`probe`);
- находит одно точное совпадение заголовка без substring/username fallback (`find-dialog`);
- выгружает строго заданный диапазон времени без частичных результатов (`export-range`);
- один раз забирает ограниченный хвост истории, затем только новые сообщения;
- может слушать `NewMessage` updates без постоянного polling истории;
- пишет локальный JSONL, помечая каждую запись `untrustedInput: true`.

Модуль не отправляет сообщения и медиа, не ставит реакции, не вступает в чаты, не импортирует
контакты, не меняет typing/read status и не скачивает вложения.

## Локальный typed read-only API

Для следующего локального слоя доступен только package entrypoint `./api`: он
принимает только уже ограниченный read-only owner и возвращает типизированные
DTO с двумя read-only методами — `listSources()` и
`getRecentMessages(sourceId, limit)`. Внутренний adapter использует уже
созданного владельца сессии, не создаёт и не подключает второй `TelegramClient`; history-read идёт
через сохранённые numeric allowlist и `GuardedExecutor` с теми же бюджетами,
интервалами, retry/FLOOD_WAIT и circuit-breaker ограничениями. Raw GramJS client,
session handle и исходящие методы в public surface не экспортируются.

Это офлайн-тестируемый контракт поверх импортированного baseline, а не
заявление о готовом target runtime. Его unit tests не проходят Telegram auth,
не читают реальные чаты и не выполняют отправку.

## Внутренние existing-session и sole-owner leases

Для RM-0018 добавлены два узких внутренних адаптера, которые намеренно не
экспортируются через `./api`:

- `existing-session-lease` принимает ровно один названный существующий
  AES-256-GCM envelope, проверяет тот же открытый file handle, расшифровывает
  StringSession только в памяти и сбрасывает свою ссылку при release;
- `sole-owner-lease` выдаёт совместимый capability только после эксклюзивного
  process lock. Lock содержит version, process-start identity, случайные
  boot/ownership nonce и удаляется только после точного ownership readback.
  Битый, неоднозначный или stale lock сохраняется и блокирует вход до отдельной
  операторской сверки. При неподтверждённом завершении дочернего транспорта
  lease атомарно пишет и перечитывает sticky-маркер, который блокирует любые
  следующие входы.

В этом срезе нет метода снятия sticky-маркера, входа/QR/кода, создания или
замены сессии, поиска файлов, фонового запуска либо Telegram-записи. Эти
адаптеры нужны только для офлайн-проверенного foreground one-shot bridge;
наличие кода само по себе не разрешает live-запуск.

## Guardrails

- только `mode: "read-only"`;
- только заранее указанные числовые ID, без `*` и username resolution;
- один процесс/одна основная MTProto-сессия;
- 6 запросов/мин, 60/час и 300/скользящие 24 часа по умолчанию;
- не меньше 2.5 секунды между запросами;
- не больше 2 повторов только для сетевых/5xx ошибок;
- `FLOOD_WAIT` никогда не ретраится немедленно: cooldown сервера + 30 секунд сохраняется на диск;
- при первичном входе разрешена ровно одна дополнительная внутренняя попытка GramJS,
  необходимая после штатного `PHONE_MIGRATE_X`; для обычного чтения лимит остаётся равным одной;
- 3 последовательных временных сбоя открывают circuit breaker на 15 минут;
- backfill, число страниц, источников, сообщений и live buffer жёстко ограничены;
- state обновляется только после успешной записи экспорта;
- range-export полностью собирается в памяти и атомарно записывается только как AES-256-GCM
  envelope — открытый JSONL на диск не попадает;
- срок хранения range-export ограничен 1–30 днями (в готовых аккаунтах — 7 дней); просроченные
  файлы удаляются при следующем запуске wrapper, а malformed-файлы сохраняются для проверки.

## Установка по правилам этой машины

Зависимость классифицирована как repo-local. Node 24/npm 11 уже предоставлены машиной. Никаких
глобальных npm-пакетов, PATH-обёрток или workstation manifest для GramJS не создаётся.

```powershell
Copy-Item .\config.example.json .\config.json
npm ci --ignore-scripts
```

`telegram` закреплён точно на `2.26.22`, а транзитивные версии и integrity — в
`package-lock.json`. Автоматически обновлять пакет нельзя: текущий npm package помечен deprecated,
а миграция на `teleproto` требует отдельного аудита совместимости.

## Подготовка

1. Получите собственные `api_id` и `api_hash` в
   [my.telegram.org → API development tools](https://my.telegram.org/apps). Не используйте чужой
   публичный API ID.
2. Скопируйте `config.example.json` в `config.json`.
3. Прочитайте действующие [Telegram API Terms](https://core.telegram.org/api/terms). Поставьте три
   compliance-флага в `true` только если источники ваши/разрешённые, экспорт не идёт в разработку
   AI/ML и условия приняты.
4. Оставьте источники выключенными до команды `discover`.

В текущем PowerShell-процессе задайте секреты; не пишите их в config и не присылайте в чат:

```powershell
$env:TG_API_ID = '12345678'
$env:TG_API_HASH = '<32 hex characters>'
```

## Однократная авторизация

Для отдельного аккаунта без чтения чатов доступен `auth --auth-only --config PATH`.
Его конфигурация содержит только `schemaVersion: 1`, `mode: "auth-only"` и
`account` с именами переменных `apiIdEnv`, `apiHashEnv`, `sessionPassphraseEnv`
и новым путём `sessionFile`. Ключи и пароли вводятся в интерактивном терминале;
значения секретов в конфигурацию не помещаются. Используйте отдельную приватную
директорию и одного владельца запуска, без `--replace-session`.

Этот режим выполняет обычный вход, включая служебную проверку состояния
авторизации Telegram, сохраняет зашифрованную сессию и отключается. Он не
читает диалоги или историю и не подключает сессию к рабочему шлюзу.
Конфигурация `auth-only` отвергается командами чтения; прежние требования
к настройкам и разрешениям архивирования остаются неизменными.

Отдельная операторская команда `bind-account --config PATH --title EXACT_TITLE
--binding PRIVATE_ABSOLUTE_PATH` использует те же account-настройки для проверки
уже сохранённой сессии. Она берёт эксклюзивный session-owner lock до расшифровки,
показывает аккаунт локальному владельцу и запрашивает одно окно до100 диалогов.
Сопутствующие поля последних сообщений отбрасываются без вывода, хранения или
передачи модели; запрос истории не выполняется. Только уникальное точное
совпадение доступной группы, подтверждённое владельцем, сохраняется в приватную
привязку после отключения клиента. Занятый lock, существующая привязка, отказ,
неоднозначность и неподтверждённое отключение блокируют результат.
Команда не запускает обслуживающий runtime и не отправляет сообщения.
В скрытых полях терминала теперь видны звёздочки; Backspace удаляет символ,
Ctrl+U очищает весь ввод, сам секрет не отображается.

```powershell
npm run auth -- --config .\config.json
```

Телефон, login code, 2FA и пароль шифрования вводятся локально. Сессионная строка не печатается.
Повторная авторизация не выполняется автоматически. Для осознанной замены используется
`--replace-session`; старый зашифрованный файл переименовывается в backup.

## Выбор источников

```powershell
npm run discover -- --config .\config.json
```

Возьмите точный numeric `peerId` только из этого ограниченного списка, добавьте его в `sources`,
задайте безопасный `id` и включите `enabled: true`. Для первого запуска
`initialBackfillMessages: 0` ставит baseline без экспорта старых сообщений; значение 1–100
экспортирует только ограниченный свежий хвост.

Для двух подготовленных аккаунтов используйте интерактивный wrapper. Секреты существуют только в
его PowerShell-процессе и очищаются после команды:

```powershell
& .\run-account.ps1 -Account account1 -Action probe
& .\run-account.ps1 -Account account1 -Action find-dialog -Title 'Тестовый диалог'
```

`find-dialog` печатает только единственное точное совпадение и numeric `peerId`. После явного
добавления этого ID в allowlist диапазон выгружается так (верхняя граница не включается):

```powershell
& .\run-account.ps1 -Account account1 -Action export-range `
  -Source matushka -From '2026-08-06T00:00:00+03:00' -To now
```

Команда спросит пароль Telegram-сессии и отдельный пароль локального экспорта длиной не менее 16
символов. Результат имеет суффикс `.range.jsonl.enc`. Для локального просмотра без создания
открытого файла используйте только собственный терминал, не pipe/redirect и не запуск через AI:

```powershell
& .\run-account.ps1 -Account account1 -Action view-export -File '<имя .range.jsonl.enc>'
```

Очистка просроченных range-export выполняется при каждом запуске wrapper и вручную:

```powershell
& .\run-account.ps1 -Account account1 -Action purge-expired
```

Это проверка при запуске, а не фоновая задача Windows. Если модуль больше не запускается, удалите
файл вручную по истечении срока. Task Scheduler без отдельного согласования не устанавливается.

## Проверка и запуск

```powershell
npm run doctor -- --config .\config.json
npm run sync -- --config .\config.json
npm run watch -- --config .\config.json
```

`watch` — foreground-процесс; остановка через Ctrl+C. Не запускайте второй экземпляр, другой
userbot или копию той же `StringSession`: lock остановит локальный дубль, а Telegram отдельно
предупреждает об `AUTH_KEY_DUPLICATED` при параллельных main-сессиях.

## Ретраи и стоп-сигналы

- `FLOOD_WAIT_X`: сохранить `cooldownUntil`, завершить процесс с кодом 3, ждать как минимум X+30 с;
- 500/RPC/network timeout: exponential backoff с full jitter, максимум 2 повтора;
- 401/403/406, revoked/expired/duplicated auth key, frozen account: без повтора, операторская проверка;
- исчерпан бюджет или открыт circuit breaker: без сетевого запроса, код 3;
- неизвестная ошибка: без повтора.

Не удаляйте `data/state.json`, чтобы «сбросить» cooldown или бюджеты: это будет обходом собственных
guardrails. Сначала дождитесь срока и разберите причину.

## Данные и ограничения

Обычный sync-экспорт находится в `data/export/<source-id>.jsonl`; точечный защищённый экспорт — в
`.range.jsonl.enc`. Все чувствительные runtime-файлы исключены из Git. Расшифрованный JSONL может
содержать персональные данные. Храните его локально и не передавайте в LLM/embeddings/training
pipeline. Модуль не является полным Telegram-клиентом,
не поддерживает sponsored messages UI и потому предназначен только для личного ограниченного
экспорта, а не для публикации как клиентское приложение.

Техническое сравнение с OpenClaw и ссылки на первичные источники находятся в [RESEARCH.md](./RESEARCH.md).
